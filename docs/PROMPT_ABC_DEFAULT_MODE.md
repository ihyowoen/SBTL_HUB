# Prompt A/B/C Default Mode V4

**Status:** `ACTIVE_CANONICAL`  
**Version:** `PROMPT_ABC_DEFAULT_MODE_V4_20260829`

## 1. Stage A — Integrated selector

Stage A is selector-only and consumes the locked expanded event universe plus current canonical comparison metadata. It does not fetch external article bodies, create `fact_sources`, create source quotes, draft card copy, declare fact safety, or declare publish readiness.

Stage A contains the complete active news-value operating rule; no Structural Value companion/override prompt is applied.

Every candidate is terminally accounted as strict, candidate review, watchlist/context, reject/support-only, reinforcement/update candidate, duplicate, or another explicitly supported outcome.

Strict/high-potential candidates emit:

- execution credibility gate;
- independent cardability gate;
- anchor classes and selection route;
- 100-point decision value score/breakdown/classification;
- publication urgency;
- prior-state/new-fact/changed-judgment chain;
- duplicate/follow-up/baseline relation;
- `related_prepass`;
- Stage B evidence targets and next confirmation points;
- earnings/policy/technology bounded questions when applicable.

Review pool is partitioned and promotable only through the authorized 0.1P path.

## 2. Stage B — Evidence and draft

Stage B receives only valid Stage A strict items (or explicitly promoted strict items). It verifies primary/body-level/official evidence, independent source ownership, date roles, event identity, and Related evidence before drafting.

A candidate with insufficient evidence becomes `draft_blocked`; weak evidence is not laundered into a card.

## 3. Stage C — Fact-safe red team

Stage C receives Stage B evidence packages/drafts. It independently checks source direction, claim support, numbers/dates/entities, stage precision, source synthesis, stale republication, unsupported causality, selection-route evidence, full-schema viability, and Related lineage.

Accepted cards become `accepted_fact_safe` only. Stage C locks `related_lineage` for accepted new cards.

## 4. Revise loops

0.2R/0.3R repair bounded evidence/draft/fact-safe defects. Selection, duplicate, staleness, or material event-identity defects return to the earliest responsible upstream stage.

No later stage may silently promote review/watchlist/reject/support/draft-blocked/deferred items without an explicitly authorized current-run review path.

## 5. Rescue-before-abandon

Uncertainty triggers a bounded verification or a concrete review question; it is not itself a terminal reason. Stage A performs no-fetch rescue by preserving the bounded question. Fetch-enabled stages search suitable official/independent alternatives before evidence-based hold/reject where permitted.

## 6. Stage provenance

Every stage output records prompt path and locked repository provenance. A stage executed from remembered text rather than the current named prompt is invalid.
