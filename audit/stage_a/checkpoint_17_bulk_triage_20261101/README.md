## 2. 바로잡은 중요한 중복 판정 오류

이전의 느슨한 URL 정규화는 `www.energy-news.co.kr/news/articleView.html?idxno=228356`과 같은 도메인·경로의 **서로 다른** `idxno` 기사들을 같은 문서로 보았다. `todayenergy.kr/news/articleView.html?idxno=...`, `theguru.co.kr/news/article.html?no=...`도 똑같은 위험이 있었다.

이번 코드에서는 `idxno`, `no`, `list_no` 등 기사 식별 파라미터를 반드시 보존한다. 신뢰할 기사 식별자가 없는 랜딩 URL은 자동으로 결합하지 않는다. Full 카드와 소스 URL이 일치하는 2건도 **출처 재사용** 가능성일 뿐 사건 동일성·경제행위 동일성·최종 중복 처분의 근거로 사용하지 않는다.

### 위험군 요약

| 출처 검토 레인 | 단위 | 첫 조치 |
|---|---:|---|
| 사건/출처 모호성 | 1 | 같은 URL의 다른 제목·다른 행위 여부 확인 |
| 기존 Full 소스 계보 연결 | 2 | 기존 카드의 경제적 사실·단계와 새 사실 비교 |

| 문맥·구조적 검토 | 756 | 집계·인터뷰·시장보고서도 낮은 점수로 즉시 제외 금지 |

숫자는 **검토 단위(1,129개)** 기준이다. `155 Source ID` 저점수 플래그와 `141 검토 단위` 저점수 레인은 중복 출처 통합과 레인 우선순위 때문에 일치하지 않는다. 다국어 제목(한국어·중국어·일본어·영어)의 행위 키워드 검색은 재현 가능한 **고재현율 후보 탐색**이며, 사실 확인이나 산업 중요도 확정은 아니다. 오탐이 예상되므로 추후 원발행 대조가 필요하다.

## 3. 대량 정식 판정 워크플로 — 빨라지되 누락되지 않는 방법

1. **문서 식별:** `STAGE_A_CP17_REVIEW_QUEUE.csv`의 1,129단위를 원문 URL 및 동일 소스 중복으로 묶는다. 1,231 Source ID 연결은 영구 보존한다.
2. **기사 내 행위 분할:** 한 종합기사의 서로 다른 기업·설비·정책·금융 집행은 `STAGE_A_CP17_ADJUDICATION_WORKSHEET.csv`에서 행을 추가해 각각 별도 `economic_event_index_in_source`를 부여한다. 동일 사건의 다수 출처는 별개 기사 카드가 아니라 지원 관계로 표시한다.
3. **증거 자동 수집 후 사람/독립 검사:** 기업 IR·공시, 정부 원문, 입찰시스템, 계통운영자 공지 등을 먼저 확인한다. 원문과 보도 날짜, 실제 발효일, 입찰공고/낙찰, 계약/착공, 연결/상업운전, 대출승인/인출, 신규·후속 단계를 **서로 분리** 기록한다.
4. **Full 계보 비교:** 기존 카드와 같은 URL이어도 기존 사건의 후속 경제행위인지 비교한다. 단순 동일 기사 URL·제목 유사도·메타데이터 점수만으로 `exclude`, `promote`, `source-only` 결론을 내리지 않는다.
5. **정식 0.1P 배치:** 각 경제행위의 소유자 증거, `prior_state`, `new_verified_fact`, `date_role`, 분모/단위, 단계 및 대표·보강 Source ID가 채워진 후 잠금 네이티브 스키마로 판정을 이관한다. 새 배치마다 **원본 전수 IDs · 금지된 main/Full/Related 변경 · 네이티브 두 검사 · 독립 QC**를 다시 확인한다.

### 구분해야 할 필드

- `source_review_unit_id`: 한 출처 문서의 다수 관측 묶음. **사건 ID 아님**.
- `independent_event_key`: 공식 근거로 확인된 경제적 행위마다 독립 부여할 ID. **현재 비어 있음**.
- `stage_a_disposition`: 공식 확인과 선행 사건 검토를 마쳐 입력할 정식 처분. **현재 비어 있음**.
- `review_priority_score_not_news_value`: 검토 순서만 결정하는 휴리스틱. 산업 점수·0.1P 판정 아님.
